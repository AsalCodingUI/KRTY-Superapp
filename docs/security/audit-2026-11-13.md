# Audit 2026-11-13: security and performance (web + Kretya Flow)

Fixed in this change and still to do. "Applied" means it is in the code;
the database items are SQL only and are **not applied to production yet**.

## Fixed

- **Sign-out left Leads open.** Signing out now closes every Leads site and
  removes its sign-in (cookies, storage) from WebKit's store; the app's own
  site keeps its data. Two paths: `afterSignOut()` (web,
  `src/shared/lib/after-sign-out.ts`) and the sign-in page loading in the
  app window (`desktop/src-tauri/src/lib.rs`, `leads::leads_reset`). The
  search's recent results are cleared too.
- **A site could make macOS open anything.** A new-window link from a site
  goes to the system only for http, https and mailto (not file:, smb:,
  other apps' schemes or `krty://`).
- **A site could reach the app's commands.** `capabilities/main.json` now
  matches the app and popover web views by label (`webviews`), not the
  whole window, whose children are the Leads views; and a Leads view may
  only load https pages that aren't the app's own or this Mac's.
- **Downloads.** Types macOS runs or opens as an app (.command, .app,
  .pkg, .webloc, .terminal …) are refused, names lose bidi controls, files
  get the quarantine flag (Gatekeeper asks), and a full name list no longer
  overwrites a file.
- **Notification spam / spoofing.** Titles 100 and bodies 300 characters at
  most, 20 a minute from all sites together (and still one per 1.5 s each).
- **Closed Leads views** (past the 3 kept) now remove their wrapper too.
- Removed the stale `/api/migrate` route.
- Performance: My Tasks no longer refetches on every open (realtime keeps
  it live; 30 s stale time); the app's release lookup checks the newest
  versions in parallel.
